The IPC Catalog

💨

Pipes (Anonymous & Named)

Mechanism: A unidirectional data channel that allows one process to write data and another to read it. In Linux, pipes are managed by the kernel as a buffer.

PRO: Extremely simple to use for parent-child processes.
CON: Unidirectional and limited buffer size (usually 64KB).
📨

Message Queues

Mechanism: A linked list of messages stored within the kernel. Unlike pipes, messages can be formatted into structures and retrieved by "type", allowing priority-based communication.

PRO: Asynchronous (sender doesn't wait) and structured data.
CON: Overhead of copying data into/out of the kernel.
🧠

Shared Memory

Mechanism: Two or more processes map the same physical memory segment into their virtual address spaces. This is the **fastest** IPC because it avoids kernel intervention for data transfer.

PRO: Maximum performance; ideal for large data (graphics, databases).
CON: Requires manual synchronization (Semaphores) to avoid race conditions.
🚦

Semaphores

Mechanism: Integer counters used to coordinate access to shared resources. They are not used to transfer data but to signal whether a resource (like shared memory) is available.

PRO: Essential for synchronization and preventing data corruption.
CON: Complex to implement correctly; prone to deadlocks.
⚡

Signals

Mechanism: Software interrupts sent to a process to notify it of an event (e.g., SIGINT on Ctrl+C). They are the simplest form of notification but carry very little data.

PRO: Extremely low overhead for simple notifications.
CON: Can only send the signal number; cannot transfer complex data.

Core IPC Mechanism Breakdown

pipe()

Creates a unidirectional channel for parent-child communication.

msgget() / msgsnd()

Creates a message queue and sends formatted messages to it.

shmat()

Attaches a shared memory segment to the process address space.

signal()

Registers a handler function to be called when a specific signal occurs.
