CPU Scheduling

How Linux manages multi-tasking and switches between processes.

1. The Process Control Block (PCB)

In Linux, every process is represented by a task_struct (the PCB). It contains all the metadata needed to manage the process lifecycle.

PID

Process Identifier

STATE

Running, Waiting, Stopped

PRIO

Dynamic Priority (Nice Value)

REGS

Register Context (Saved here during switch)

FILES

List of open file descriptors

MEM

Memory Management Info (Page Tables)

2. Context Switching Mechanism

When the Scheduler decides to switch tasks, it triggers a context switch. This is a CPU-intensive operation where the hardware state is swapped.

PCB (Process A)
Registers: [saved]
CPU CORE
Running: Process A
PCB (Process B)
Registers: [idle]

3. Completely Fair Scheduler (CFS)

Since Kernel 2.6.23, Linux uses **CFS**. Unlike traditional schedulers, CFS doesn't use standard time slices. Instead, it uses a **Red-Black Tree** to track 'vruntime' (virtual runtime).

Vruntime

The amount of time a process has spent on the CPU. CFS always picks the process with the lowest vruntime.

Nice Values

Range: -20 to 19. A lower nice value means higher priority, causing vruntime to increase slower.

Target Latency

The period during which every runnable task should run at least once.

4. Classic Algorithms & Metrics

Turnaround Time

Finish Time - Arrival Time

Waiting Time

Turnaround Time - Burst Time

Response Time

First Run Time - Arrival Time

Round Robin (RR)

Preemptive. Each process gets a fixed time quantum. Great for time-sharing systems.

Multilevel Feedback Queue

Processes move between queues based on their behavior (I/O bound vs CPU bound).

Shortest Remaining Time First

Preemptive version of SJF. Swaps if a new process arrives with a shorter burst.
